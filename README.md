# 社区停车管理系统

一个面向 **业主 / 物业代表 / 管理员** 三类角色的社区车位管理系统，实现「车位申请 → 物业审核 → 管理员分配 → 车位状态释放」的完整业务闭环。

Node.js + Express + SQLite 全栈实现，前端为原生 HTML5 / CSS3 / JavaScript，无需构建工具，克隆即可运行。

## 功能特性

### 业主端
- 注册与登录（账号密码登录，Session 维持登录态）
- 查看全部车位与可用车位，按区域、楼层、价格展示
- 提交车位申请（含申请理由），并限制「同时仅能存在一条待审核申请」「已有车位不可重复申请」
- 查看我的申请记录（待审核 / 已通过 / 已拒绝）与当前已分配车位

### 物业代表端
- 查看待审核申请（含业主楼栋、单元等关联信息）
- 审核通过 / 驳回申请，并填写审核意见
- 查看车位列表、车位分配记录、我的审核历史

### 管理员端
- 数据看板：待审核数、车位总数、已占用数、分配数、业主数、物业代表数
- 车位管理：新增 / 编辑 / 删除车位（编号唯一校验，已占用车位禁止删除）
- 申请审核与车位分配：审核通过后自动写入分配记录（1 年期）并将车位置为占用
- 分配管理：取消分配时自动回滚车位状态为「可用」
- 用户管理：查看与删除业主、物业代表账号（级联清理其申请与分配数据）

## 技术栈

| 层次 | 技术 |
| --- | --- |
| 前端 | HTML5、CSS3、原生 JavaScript（Fetch API、DOM 动态渲染） |
| 后端 | Node.js、Express 4 |
| 数据库 | SQLite（sql.js，数据库文件本地持久化） |
| 会话与安全 | express-session、bcryptjs 密码加盐哈希 |

## 快速开始

```bash
# 1. 安装依赖
npm install

# 2. 启动服务（默认 3000 端口）
npm start
```

浏览器打开 http://localhost:3000 即可访问。数据库文件首次启动时自动创建并写入种子数据。

> 可通过环境变量 `SESSION_SECRET` 覆盖默认的 Session 密钥：`SESSION_SECRET=your-secret npm start`

## 数据库设计

共 6 张表：

| 表名 | 说明 |
| --- | --- |
| `admins` | 管理员账号 |
| `owners` | 业主账号（含楼栋、单元、联系方式） |
| `representatives` | 物业代表账号（含所属部门） |
| `parking_spots` | 车位信息（编号、区域、楼层、状态、价格、备注） |
| `parking_applications` | 车位申请（申请人、目标车位、状态、审核人与审核意见） |
| `parking_assignments` | 车位分配记录（起止日期、状态） |

关键设计：`parking_applications` 与 `parking_assignments` 通过 `owner_id` 关联业主，`parking_assignments` 关联 `parking_spots` 以同步车位占用状态，取消分配时自动回滚。

## 接口一览

所有接口均为 JSON 交互，统一返回 `{ success, message?, data? }` 结构，共 **25 个接口**，按角色分为 4 组：

| 路由前缀 | 数量 | 说明 |
| --- | --- | --- |
| `/api/auth` | 4 | 登录、注册、退出、获取当前登录用户 |
| `/api/owner` | 5 | 车位查询、提交申请、我的申请、我的车位 |
| `/api/representative` | 5 | 待审列表、审核申请、车位/分配查询、审核历史 |
| `/api/admin` | 11 | 车位 CRUD、申请审核、分配管理与取消、用户管理、统计看板 |

## 安全设计

- **密码加密存储**：注册与登录均使用 `bcrypt` 加盐哈希，数据库中不落明文；对早期版本遗留的明文密码实现了**启动时自动升级迁移**（幂等，仅处理未哈希数据）。
- **SQL 注入防护**：所有查询均使用参数化语句（`?` 占位符绑定），表名通过角色白名单映射，避免字符串拼接。
- **越权访问拦截**：每个角色路由均挂载权限中间件，在接口层校验 Session 中的角色，未登录或角色不符直接拒绝。
- **敏感配置外置**：Session 密钥通过环境变量注入，不硬编码。
